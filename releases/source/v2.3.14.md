# Jingdu v2.3.14 Source Release

version: v2.3.14
kind: source-release
google_play_production: false

This patch release advances Jingdu from v2.3.13 to close the final Reader/TTS hardening backlog identified after the continuity release. It focuses on long-session stability, continuous-mode memory bounds, TTS lifecycle efficiency, native-selection correctness, maintainability, physical qualification evidence and build/dependency hygiene. It does not claim Google Play production qualification or physical-device TTS/Reader soak PASS; those remain external evidence tracked by #79.

The exact pre-release product main SHA is `13c275a1486d899b32b2c8b58349b33f3acadc9a`, the normal-merge result of PR #185. PR #185 final head `535e9c63d63fc2ada2a7df629d4fd6566e810d6d` passed CI Contracts #444, canonical PR CI #1796, Reader Performance PR #272 and Pose Studio #232. It is the repository-side integration point for the final hardening work originally isolated across PRs #167, #168, #176, #182 and their superseded quality/dependency/CI rollups.

Continuous Reader raster memory is now genuinely viewport-bounded. The native renderer retains at most five ARGB tiles in an LRU rather than rasterizing and retaining the entire bounded 4 KiB text window, prewarms only visible/adjacent tiles, detaches scroll sinks when the viewport is disposed, aborts stale fling/touch state and drops old raster references without recycled-bitmap races. Continuous single/double-tap arbitration matches paged behavior, paged left/right navigation semantics are no longer reused in continuous mode, and TalkBack/touch-exploration switching is reactive.

Continuous TTS no longer forces a full StaticLayout/raster rebuild on every chunk. The moving speech range is drawn as a lightweight native overlay, same-window source movement reuses the existing layout/raster, and queued TTS chunks publish their exact next source offset so ReaderTtsPlayer no longer calls ReaderController.speech() a second time. Activity-side voice discovery is lazy and engine-ready driven rather than using a fixed delay, while playback-service state is projected without starting a second TTS path for users who never use read-aloud.

Native continuous selection now resolves the first long press directly to an exact source-coordinate word range. The fallback Compose selection state no longer clears a native selection it did not own, and the regression suite targets the real native viewport so 200% font-scale/inset geometry cannot move the gesture into Reader chrome. Functional instrumentation contains 16 JingduUiTest cases at both normal and 200% font scale.

Reader/TTS physical soak evidence is stronger without weakening any product SLO. Reader and TTS long sessions sample every 10 seconds, retain total PSS plus Java-heap, native-heap and graphics memory, exclude the first five minutes from trend analysis, and enforce post-warm-up growth ceilings of 64 MiB/hour for total PSS and 32 MiB/hour for each component. A synthetic slope regression test proves stable traces pass and deliberate leak-shaped traces fail. These harnesses remain external qualification tools; no physical-device PASS is claimed by this source release.

Maintainability work splits continuous native rendering from ReaderFastText, status/selection/HUD support from ReaderScreen, and TTS catalog/playback Intent ownership from MainActivity into dedicated coordinators. The architectural contracts were updated to validate those module boundaries without relaxing Reader correctness, source-coordinate, accessibility or release requirements.

The final hardening rollup also retires redundant Pose Studio candidate/beta fan-out while preserving immutable commercial-beta provenance. Pose Studio candidate publication now triggers only from the product-specific Pose Studio workflow and remains fail-closed on exact-SHA CI / Pose Studio / CI Contracts evidence. The historical automatic commercial-beta publisher is retired; this does not change Pose Studio's production-v1 status.

Build/dependency hygiene is updated as one qualified set: actions/setup-java 6.0.1 across active workflows, Media3 common/session 1.11.1, protobuf protoc/kotlin-lite 4.36.2, Kotlin Compose plugin 2.4.20, Android Gradle Plugin application/test 9.4.1 and Gradle wrapper 9.6.0. Third-party inventory, notices and terminal contracts were updated with the dependency versions rather than bypassed.

On PR #185 exact head, Reader Performance #272 passed page-turn P95/P99 `58.191 / 66.114 ms` over 140 samples, continuous-scroll `51.257 / 67.172 ms` over 769 samples, and Chapters/Settings `82.052 / 94.363 ms` over 334 samples. Canonical baseline/startup profiles contained `23783 / 22577` rules. Hosted Reader performance thresholds, frozen baselines, sample floors and physical SLO ceilings were not widened.
