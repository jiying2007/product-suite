# Jingdu v2.3.12 Source Release

version: v2.3.12
kind: source-release
google_play_production: false

This patch release advances Jingdu from v2.3.11 after the comprehensive Reader P0-P2 hidden-risk hardening landed through PR #151. It freezes the post-v2.3.11 product fixes for continuous reading, long-session TTS, safe drawing insets, portable backup privacy, storage/lifecycle durability, large-file import resilience and recovery behavior. It does not claim Google Play production qualification or physical-device TTS/Reader soak PASS; those remain external evidence tracked by #79.

The exact pre-release product main SHA is `179fd565fad811542c6e95e8efc6a0d5ace176c9`, the normal-merge result of PR #151. PR #151 final head `0ebe1c75391d43b9da1c540918696eb695236255` passed CI Contracts #335, canonical CI #1687 and Reader Performance PR #190. The normal merge adds no file-content drift relative to that head.

PR #151 closes the audited P0 privacy gaps by making portable annotation backup schema 5 omit automatically captured source excerpts/re-anchor context while explicitly declaring portable user-authored text, and by requiring TextToSpeech to bind an installed `isNetworkConnectionRequired=false` voice before book text is spoken. Default-engine playback can no longer silently delegate voice choice to a network-required voice. A same-generation completion watchdog preserves stale-callback protection while recovering from TTS engines that omit utterance ids.

The durability/lifecycle hardening makes Reader/TTS progress persistence O(1), removes unbounded main-thread waits at Activity pause/destroy and TTS service teardown, bounds annotation lifecycle flush latency, atomically replaces Room annotation/stat tables, and adds a durable private rollback journal for interrupted cross-store portable restores. The private rollback journal may retain full local annotation anchor state solely for rollback; that private state is never emitted by the portable export.

TXT import is now bounded to 512 MiB with private-storage reserve checks, generates progressive first-readable preview from the same single provider stream as the final import, sanitizes provider filenames, recovers complete content-addressed private book directories into the catalog after catalog loss, and prunes only stale incomplete import debris. Custom font import is streamed rather than double-buffered, and large-book deletion leaves the UI thread.

Reader correctness hardening makes the paged layout cache collision-safe by retaining exact bounded source/display identity rather than trusting a 32-bit String hash, and removes the wide monitor around continuous multi-window prefetch so background warming cannot monopolize the same lock across several handoff windows. Folder Library no longer silently truncates at 500 TXT files; it supports up to 10,000 per selected root and fails visibly rather than hiding additional books.

The physical TTS qualification workflow now supports both `background` and `foreground-continuous` 30/60 minute modes on a real self-hosted Android device. Foreground-continuous mode opens the deterministic 100 MiB book in the production continuous Reader while real TTS drives source-position synchronization; retained evidence must prove stable PID, monotonic persisted and foreground Reader positions, bounded PSS and no target ANR/OOM/fatal crash. Workflow presence is not physical PASS.

Hosted Reader performance thresholds, frozen baseline, sample floors and physical SLO thresholds were not widened. On PR #151 exact head, Reader Performance #190 passed page-turn P95/P99 45.220/56.732 ms, continuous-scroll 25.894/35.334 ms, and Chapters/Settings 69.913/90.314 ms. The exact-main merge SHA then passed canonical CI #1688 with page-turn P95/P99 57.459/65.586 ms over 115 retained samples, continuous-scroll 59.828/74.244 ms over 761 samples, and Chapters/Settings 101.722/125.195 ms over 317 samples, all against the unchanged frozen gates. CI #1688 also passed Android functional, 16 KiB/native compatibility, Android build, native-core, terminal, Harmony, Play-store and repository-topology jobs; canonical Reader baseline/startup profiles contained 24700 / 23664 rules.

The release-only branch changes exactly three files: Jingdu Android default versionCode `17 -> 18`, versionName `2.3.11 -> 2.3.12`, root Android releaseVersion `2.3.11 -> 2.3.12`, and this source-release manifest. No Reader product behavior, Billing behavior, dependency, benchmark workload, hosted threshold, baseline, sample floor, physical SLO threshold or release-signing policy changes in this branch.

After fresh exact-head release PR gates pass, the branch may be normal-merged only with its exact expected head. The resulting exact-main release CI must create annotated `v2.3.12` provenance, publish the debug-signed Android artifact plus checksums/signing-certificate evidence, and finalize the immutable GitHub Release before v2.3.12 is used for physical qualification. This source release does not claim Google Play production qualification.
