# Jingdu v2.3.16 Source Release

version: v2.3.16
kind: source-release
google_play_production: false

This hotfix release advances Jingdu from v2.3.15 to close the remaining user-visible Reader regressions reported after that release: Android system TTS could still terminate with an engine error instead of recovering automatically, paged text could still appear discontinuous because a partially clipped bottom line was counted as consumed, and page wrapping could diverge from the actual rendered width and styled/TTS-highlight layout.

The exact pre-release main SHA is `e2543605ec2db11aa008f0c808d237a011515fab`, the normal-merge result of PR #190. PR #190 final head `fa3e10566f46901d920d9dc0a38659e05f97931d` passed CI #1834, CI Contracts #482 and Reader Performance PR #305 before merge. The merged exact-main then passed canonical CI #1835, CI Contracts #483 and Pose Studio #238 including API 36 instrumentation.

TTS playback is now self-healing rather than repeatedly retrying the same failed TextToSpeech instance. ReaderTtsPlayer owns a rebuildable engine, keeps the user's rate, pitch and selected voice settings across rebuilds, allows slow engines time to complete OnInit, recreates engines after retryable provider failures, and clears a failing saved vendor-engine preference before falling back to Android's current default engine. If Android silently resolves an unavailable requested engine to another installed default engine, Jingdu keeps the successful playback instance but clears the stale saved package so future starts do not repeat the invalid selection. TtsController reapplies audio attributes, rate, pitch, language and voice after OnInit(SUCCESS), contains vendor binder/runtime failures, and only accepts an already-active offline voice when it matches the document language candidates. The offline/local TTS privacy contract remains unchanged.

The production-path TTS instrumentation now requires real speech queue progress rather than merely any service state broadcast. On exact-main, `TtsPlaybackServiceSmokeTest` passed 2/2 with zero failures and zero errors:
- `realPlaybackBridgeStartsServiceWithoutProcessCrashAndPublishesState` requires the service to queue a real next source offset without a terminal engine error.
- `missingSavedEngineFallsBackToSystemDefaultAndQueuesSpeech` stores a deliberately nonexistent engine package and requires Android-default fallback, real queued speech and cleanup of the invalid saved preference.

Paged Reader now consumes only lines whose full line box is inside the measured content height. A line that merely intersects the viewport bottom is never treated as fully read, so the following page begins at the exact source boundary after the last fully visible line rather than after clipped text. Extremely large accessibility text still keeps paging reachable by allowing the first oversized line to make progress.

Pagination and rendering now share one authoritative page width. ReaderScreen computes the same adaptive single/two-column width used by the actual page container and passes that exact pixel width into ReaderPageLayoutCache. The previous independent hard-coded width cap no longer determines source advancement. Page measurement remains fixed-cost StaticLayout with phrase-aware CJK line breaking, and styled/TTS-highlight fallback uses the same phrase-aware policy so highlighting does not change CJK wrapping. Plain/heading pages reuse the exact measured layout/raster. The 1x1 raster wrapper itself remains fixed-cost and does not perform unnecessary high-quality line solving.

Paged chrome keeps a stable cutout/status/navigation-safe content area while reclaiming unnecessary blank space: the progress rail is 32dp and the stable bottom chrome reserve is 116dp instead of 132dp. This increases usable text height without allowing text under the persistent controls, while the source boundary still derives only from fully visible lines.
