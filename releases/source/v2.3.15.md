# Jingdu v2.3.15 Source Release

version: v2.3.15
kind: source-release
google_play_production: false

This hotfix release advances Jingdu from v2.3.14 to address three Reader regressions reported after the previous immutable release: TTS could crash immediately when playback was started, paged text could appear discontinuous across page turns because Reader chrome overlapped text that had already been counted as consumed, and TXT Health / TXT Doctor content could be difficult or impossible to reach by scrolling on some device/window/font configurations. This source release does not claim Google Play production qualification or physical-device TTS/Reader soak PASS.

The exact pre-release main SHA is `a571050e20508258f602445ec7d3b9c5c5b5a6ba`. Product behavior landed through PR #187 at exact-main `1a590c6f50b7558e4a471138f91ca69998f549ce`; PR #187 final head `3d01bcf33d94e5b1c3a659f7e13a1fe325f9603c` passed CI Contracts #469, canonical PR CI #1821 and Reader Performance PR #295 before merge, and exact-main then passed CI #1822, CI Contracts #470 and Pose Studio #235. PR #189 subsequently changed only the hosted 200% native-selection test observation window from 5 to 10 seconds without retrying the gesture or changing Reader runtime behavior; its exact head `0ba11e95cdf70c3273600e4aa0769fc4342f2dc4` passed CI #1824, CI Contracts #472 and Reader Performance PR #297 before normal merge to this pre-release main.

TTS startup no longer forces an explicit foreground-service start from Reader UI. MediaSessionService owns the foreground transition when playback is actually active, eliminating the system deadline window that could turn slow or broken TTS-engine initialization into a process crash. Playback service dispatch is fail-soft, saved vendor engines that can no longer be constructed are cleared and retried with the platform default, and vendor binder/runtime failures around initialization, speech configuration, stop and completion polling are contained rather than escaping into the Activity. A production-path instrumentation smoke starts TtsPlaybackService through TtsPlaybackBridge against a real imported TXT and requires service state publication instead of a process crash.

Paged Reader now reserves a stable chrome-safe text area for the top Reader bar and bottom progress/control dock in addition to display cutout, status-bar and navigation/gesture insets. Text hidden beneath persistent Reader chrome is therefore no longer included in the measured source range consumed by the current page, preventing the next page from appearing to skip text. Continuous Reader keeps its existing viewport policy.

TXT Health and TXT Doctor use bounded LazyColumn content with navigation-bar padding and disabled sheet-drag gesture competition. Both ModalBottomSheet surfaces explicitly skip the partially-expanded state so the sheet opens fully before internal list scrolling takes ownership. Doctor actions are separate list items so each remains individually reachable on small screens and at large font scale. Functional UI regressions cover both terminal action groups.

The Android functional CI contract was also corrected so the 200% font-scale gate derives the expected JingduUiTest count from source instead of hard-coding an obsolete count. On PR #187 final head the normal source-bound instrumentation suite passed, the 200% font-scale JingduUiTest suite passed 18/18, and the independent 16 KiB native compatibility gate passed. Reader Performance #295 on the exact PR head passed page-turn P95/P99 `53.006 / 62.932 ms` over 135 samples, continuous-scroll `49.020 / 59.708 ms` over 783 samples, and Chapters/Settings `85.082 / 99.094 ms` over 338 samples. Canonical baseline/startup profiles contained `23515 / 22574` rules. The retained Reader artifact is ID `11260580718`. No benchmark workload, hosted baseline, sample floor, physical SLO ceiling or Reader performance threshold was widened for this hotfix.
